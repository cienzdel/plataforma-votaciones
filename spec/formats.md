# Data formats

> **Status: draft 0.1, pending review by a second person (milestone H2).** Normative. The key words MUST, MUST NOT, SHOULD and MAY are to be interpreted as described in RFC 2119 and RFC 8174 when, and only when, they appear in all capitals.

This document defines every byte string and JSON document that the platform publishes or exchanges and that a verifier needs. The protocol that produces them is in [`protocol.md`](protocol.md), the counting methods in [`methods.md`](methods.md) and the draws in [`draws.md`](draws.md).

## 1. Conventions

### 1.1 Notation

| Symbol | Meaning |
|---|---|
| `H(x)` | SHA-256 of the byte string `x` (32 bytes). |
| `a ‖ b` | Concatenation of byte strings. |
| `utf8(t)` | UTF-8 encoding of the text `t`. |
| `u64be(n)` | The integer `0 ≤ n < 2^64` as 8 bytes, big-endian. |
| `tag(t)` | `utf8(t) ‖ 0x00`. A domain-separation prefix; `t` is ASCII. |
| `JCS(v)` | Canonical JSON serialisation of the value `v` (RFC 8785), as UTF-8 bytes. |
| `HJ(v)` | `H(JCS(v))`. |
| `hex(x)` | Lowercase hexadecimal encoding of the byte string `x`, with no prefix. |

### 1.2 Byte strings in JSON

Every byte string inside a JSON document is written as `hex(x)`: lowercase, even length, no `0x`. Implementations MUST reject uppercase hex. Hashes are therefore 64 characters long.

### 1.3 Restricted JSON profile

All JSON documents in this specification MUST satisfy the following restrictions. With them, RFC 8785 serialisation is fully determined and easy to reproduce in any language.

- Values are objects, arrays, strings, `true`, `false`, `null` and **integers** in the range `−(2^53 − 1) … 2^53 − 1`. Floating-point numbers, exponents and `-0` MUST NOT appear. Fractions are written as two-element arrays `[p, q]` of integers with `q > 0`.
- Object member names match `^[a-z][a-z0-9_@-]*$` (ASCII), so sorting by UTF-16 code units equals sorting by bytes. Hyphens and `@` appear because tallies and results are keyed by ids and cell keys (`c-1`, `c1@comms`).
- Strings are valid Unicode (no lone surrogates) and SHOULD be in Unicode Normalisation Form C. Implementations MUST NOT normalise strings before hashing: what is hashed is what was published.
- No duplicate member names.

Under these restrictions, `JCS(v)` is the compact serialisation with members sorted by name, the separators `,` and `:` with no whitespace, non-ASCII characters written literally in UTF-8, and only `"`, `\` and the control characters U+0000–U+001F escaped (as `\b`, `\t`, `\n`, `\f`, `\r` or `\u00xx` with lowercase hex). Implementations SHOULD use an existing RFC 8785 library and MUST pass the vectors in [`cases/`](cases/) of kind `jcs`.

### 1.4 Identifiers

| Identifier | Format | Generated by |
|---|---|---|
| `voting_id` | 16 random bytes from a CSPRNG, written as `hex` (32 characters). | Server, when the voting is created. |
| Candidate, slate and post ids (`cand_id`, `post_id`) | `^[a-z][a-z0-9-]{0,31}$`, unique within the voting. MUST NOT be one of the reserved words `for`, `against`, `blank`, `abstain`, `against_all`, `marked`, `unmarked`, `status`. | Officials, when the voting is created. |
| Degree ids | `^[a-z][a-z0-9-]{0,31}$`. | Profile. |
| Profile id | `^[a-z][a-z0-9-]{0,63}$`. | Profile. |

Ids carry no personal data. Names live in the separate candidates table (§6), so they can be removed later without breaking any hash.

### 1.5 Timestamps

Timestamps are strings in RFC 3339 UTC with second precision: `YYYY-MM-DDTHH:MM:SSZ`. They appear only at voting level (opening, closing). **No timestamp is ever attached to a ballot, token or credential.**

## 2. Cryptographic objects

### 2.1 Signing key

- Scheme: RFC 9474, variant **RSABSSA-SHA384-PSS-Randomized**: hash SHA-384, MGF1 with SHA-384, salt length 48 bytes, message randomisation with a 32-byte prefix.
- Modulus exactly 3072 bits; public exponent 65537.
- `public_key`: `hex` of the DER-encoded SubjectPublicKeyInfo with the `rsaEncryption` algorithm identifier (OID 1.2.840.113549.1.1.1, NULL parameters).
- `key_fingerprint = H(DER SubjectPublicKeyInfo)`, written as `hex`.

Verifiers MUST check the modulus length and the exponent.

### 2.2 Token

The token is the **prepared message** of RFC 9474 (§4.1, `Prepare` with randomisation), 80 bytes:

```
token = prefix ‖ voting_id ‖ r
        32 B     16 B        32 B
```

- `prefix`: 32 random bytes added by `Prepare`.
- `voting_id`: the 16 bytes of the voting.
- `r`: 32 random bytes from the client's CSPRNG.

The bytes `token[32:48]` MUST equal the voting's `voting_id`. The token is the unit of uniqueness: a token can be spent once.

### 2.3 Signature

`sig` is the 384-byte RFC 9474 signature over `token`. It is a standard RSASSA-PSS signature (SHA-384, MGF1-SHA-384, salt length 48) over `token` and MUST verify with any RSASSA-PSS implementation given those parameters. A **credential** is the pair `(token, sig)`.

### 2.4 Ballot secret and cell ids

The client draws a ballot secret `s` of 32 random bytes per ballot. For each cell key `c` (§3), the cell id is:

```
id_c = H( tag("pv/cell/v1") ‖ s ‖ voting_id ‖ utf8(c) )
```

`s` and `voting_id` have fixed lengths, so the encoding is unambiguous. `id_c` MUST NOT depend on the token, because the token is public ([ADR-0005](../PLAN/adr/0005-tablon-desagregado.md)).

## 3. Ballots, cells and values

A ballot is an object that maps each **cell key** of the voting to one **value**. Every cell of the voting MUST be present: abstaining is a value, not a missing cell. The cells and their allowed values depend on the method:

| Method | Cell keys | Allowed values |
|---|---|---|
| `yes_no` | `q` | `for`, `against`, `blank`, `abstain` (the profile MAY hide `blank` or `abstain`) |
| `single_winner` | `choice` | each `cand_id` of the voting, `blank`, `against_all`, `abstain` |
| `posts` | `<cand_id>@<post_id>` for each post a candidate applied to | `for`, `against`, `abstain` |
| `limited_vote` | `status`, plus one key `<cand_id>` per candidate | `status`: `marked`, `blank`, `abstain`. Candidate cells: `marked`, `unmarked` |

Validity rules beyond the table, checked by the reception service on each complete ballot ([`protocol.md`](protocol.md) §6):

- `limited_vote`: if `status` is `marked`, between 1 and `k` candidate cells are `marked`; if `status` is `blank` or `abstain`, all candidate cells are `unmarked`. `k` is defined in [`methods.md`](methods.md) §5.
- Values hidden by the profile MUST be rejected.

**Tallies.** `tallies[c][v]` is the number of ballots whose cell `c` has value `v`. A tally object lists every cell and every allowed value of that cell, including zeros. For every cell, the sum over its values equals the number of ballots `V`.

## 4. Rules

The effective rules of a voting are fixed when it opens, because `quorum` depends on the call in force at that moment, and never change afterwards. They are published in the opening notice (§12).

```json
{
  "electorate_filter": null,
  "method": "yes_no",
  "min_attendance": null,
  "mode": "secret",
  "params": { "base": "cast", "rule": "simple" },
  "profile": { "hash": "…64 hex…", "id": "pleno-ciencias", "version": "1.0.0" },
  "quorum": [1, 3],
  "timing": "live"
}
```

| Member | Type | Meaning |
|---|---|---|
| `profile` | object | `id`, `version` (SemVer string) and `hash` = `HJ(profile document)` of the profile in force. |
| `method` | string | `yes_no`, `single_winner`, `posts` or `limited_vote`. Assent has its own document (§8). |
| `params` | object | Method parameters, defined in [`methods.md`](methods.md). |
| `mode` | string | `secret` (blind signatures), `roll_call` (electronic, named), `manual` (show of hands, totals entered by the officials) or `paper` (paper ballots, totals entered by the officials). |
| `timing` | string | `live` or `final_link` (end-of-session link). |
| `quorum` | fraction | Quorum of the call in force when the voting opens (e.g. `[1, 3]` or `[1, 4]`). |
| `min_attendance` | fraction or `null` | Minimum attendance required by the method (e.g. `[1, 2]`). |
| `electorate_filter` | string or `null` | Degree id restricting the electorate and the candidates, or `null`. |

`rules_hash = HJ(rules)`.

## 5. Bulletin board

The board is the public record of one voting. It is published once, when the voting is closed or annulled.

```json
{
  "candidates_hash": "…",
  "cells": { "q": [["<id_c hex>", "for"], ["<id_c hex>", "against"]] },
  "closed_at": "2027-03-10T18:42:00Z",
  "counters": {
    "issued": 2, "members": 45, "present": 30, "proxies": 1,
    "received": 2, "rights": 31, "session_members": 45, "session_present": 30
  },
  "draw": null,
  "key": { "fingerprint": "…", "public_key": "…" },
  "opened_at": "2027-03-10T18:30:00Z",
  "participation": [["<token hex>", "<sig hex>"], ["<token hex>", "<sig hex>"]],
  "quorum": { "forced": null, "met": true, "min_attendance": null, "required": 15 },
  "result": { "outcome": "approved" },
  "roll_call_hash": null,
  "rules": { "…": "…" },
  "rules_hash": "…",
  "status": "closed",
  "tallies": { "q": { "abstain": 0, "against": 1, "blank": 0, "for": 1 } },
  "title": "Approval of the minutes",
  "type": "board",
  "version": 1,
  "voting_id": "…32 hex…"
}
```

| Member | Meaning |
|---|---|
| `type`, `version` | `"board"`, `1`. |
| `voting_id`, `title` | Id and public title of the voting. The title MUST NOT contain personal data. |
| `status` | `closed` or `annulled`. An annulled board adds `annulment: {"reason": "…"}` and has `result: null`. |
| `opened_at`, `closed_at` | Voting-level timestamps. |
| `rules`, `rules_hash` | §4. |
| `counters` | See below. |
| `quorum` | `required` and `met` for the quorum; `min_attendance`: `null` or `{required, met}`; `forced`: `null` or `{"reason": "…"}` if the officials opened without quorum or minimum attendance. |
| `key` | `public_key` and `fingerprint` (§2.1). `null` unless `mode` is `secret`. |
| `participation` | `secret` only: array of `[token, sig]` pairs sorted by `token` (bytewise, which equals sorting the hex strings). Otherwise `null`. |
| `cells` | `secret` only: object mapping each cell key to an array of `[id_c, value]` sorted by `id_c`. Otherwise `null`. |
| `tallies` | §3. For `secret`, derived from `cells`; for the other modes, entered or computed by the server. |
| `draw` | `null` or the draw document that fixes the tie-break order of this voting ([`draws.md`](draws.md) §5). |
| `result` | Output of the method ([`methods.md`](methods.md)), or `null` if annulled. |
| `candidates_hash` | `HJ(candidates table)` (§6), or `null` if the voting has no candidates. |
| `roll_call_hash` | `roll_call` only: `HJ(roll-call list)` (§7). Otherwise `null`. |

**Counters.**

| Counter | Meaning |
|---|---|
| `session_members` | Members of the body, frozen when the session opened. |
| `session_present` | Members present in the session when the voting opened (in person or remote). |
| `members` | Members in the electorate of this voting (after `electorate_filter`). Equals `session_members` without a filter. |
| `present` | Present members in the electorate, from the attendance snapshot. |
| `proxies` | Proxy votes in the snapshot: valid delegations from electorate members to present members. |
| `rights` | Voting rights in the snapshot. MUST equal `present + proxies`. |
| `issued` | Credentials issued (`secret`), or `null` in other modes. |
| `received` | Ballots counted: `len(participation)` in `secret`; the number of named votes in `roll_call`; the ballots entered in `manual` and `paper`. |

In `secret` mode, `received ≤ issued ≤ rights` MUST hold. In other modes, `received ≤ rights` MUST hold.

`board_hash = HJ(board)`.

## 6. Candidates table

Published next to the board, and the only place with names.

```json
{
  "candidates": [ { "id": "c1", "name": "Ana Ejemplo" } ],
  "posts": [ { "id": "comms", "name": "Communication" } ],
  "type": "candidates",
  "version": 1,
  "voting_id": "…"
}
```

`posts` is `[]` except for the `posts` method. A slate's `name` lists its members and the position each one would take. When the retention period ends, the table can be deleted; its hash stays in the board.

## 7. Roll-call list

For `roll_call` votings: `{"type": "roll_call", "version": 1, "voting_id": "…", "votes": [{"member": "<name>", "value": "<value>"}]}`, sorted by `member`. Published next to the board, with the same retention as the candidates table.

## 8. Assent record

```json
{
  "closes_at": "2027-03-12T22:59:00Z",
  "electorate_filter": null,
  "members": 45,
  "objections": 0,
  "outcome": "approved",
  "profile": { "hash": "…", "id": "pleno-ciencias", "version": "1.0.0" },
  "sent_at": "2027-03-10T09:00:00Z",
  "title": "…",
  "type": "assent",
  "version": 1,
  "voting_id": "…"
}
```

`objections` counts the objections not withdrawn at `closes_at`. `outcome` is `approved` or `next_plenary` ([`methods.md`](methods.md) §7). The names of the people who objected go to the minutes, not to this record.

## 9. Hash chain

Every published document of type `board`, `draw` (stand-alone draws, [`draws.md`](draws.md)) or `assent` is appended to a single chain per body:

```
record      = { "board": hex(HJ(document)), "prev": hex(previous record_hash) }
record_hash = HJ(record)
```

- For the first record, `prev` is 64 zeros.
- The member is called `board` for every document type (the name is kept from [ADR-0006](../PLAN/adr/0006-cadena-de-hashes-y-anclaje.md)).
- The chain file in the data repository is:

```json
{
  "records": [
    { "board": "…", "path": "2027/03/10/<voting_id>.board.json", "prev": "000…000", "record_hash": "…" }
  ],
  "type": "chain",
  "version": 1
}
```

`path` is informative and is not hashed. A verifier MUST recompute every `record_hash` from `prev` and the hash of the document at `path`, and check that each `prev` equals the previous `record_hash`.

### 9.1 Layout of the data repository

- The chain file is `chain.json` at the root. Every `path` is relative to the root.
- A board is published as `<name>.board.json`. Next to it, with the same `<name>`:
  - `<name>.opening.json`: its opening notice (§12), always;
  - `<name>.candidates.json`: its candidates table (§6), when `candidates_hash` is not `null`;
  - `<name>.roll_call.json`: its roll-call list (§7), when `roll_call_hash` is not `null`.
- Stand-alone draws and assent records are chained documents of their own and need no companion file.
- Candidates tables and roll-call lists MAY be deleted when their retention period ends; their hashes stay in the boards.

## 10. Receipt

Stored by the voter's browser and downloadable.

```json
{
  "ack": "…",
  "answers": { "q": "for" },
  "s": "…64 hex…",
  "sig": "…768 hex…",
  "token": "…160 hex…",
  "type": "receipt",
  "version": 1,
  "voting_id": "…"
}
```

`ack = HJ({"answers": …, "s": …, "sig": …, "token": …, "voting_id": …})`, the acknowledgement returned by the reception service ([`protocol.md`](protocol.md) §6). **Anyone holding a receipt can see the vote in it.**

## 11. Profile

A profile is a versioned JSON document of a body. Only the members that affect counting are normative here; texts and display options MAY be added under `texts`.

| Member | Type | Meaning |
|---|---|---|
| `type`, `version` | `"profile"`, `1` | |
| `id`, `profile_version` | strings | Profile id and its SemVer version. |
| `body` | string | Name of the body. |
| `status` | string | E.g. `"based on regulations pending ratification"`. |
| `quorum` | array of fractions | Quorum per call, in order (e.g. `[[1, 3], [1, 4]]`). |
| `second_call_after_minutes` | integer | Minutes after which the second call can be activated. |
| `max_proxies` | integer | Maximum proxy votes held by one person. |
| `degrees` | array | `[{"id", "name"}]`. |
| `assent_min_days` | integer | `N` in [`methods.md`](methods.md) §7. |
| `assent_excluded` | array of strings | Matters that cannot be decided by assent. |
| `timezone` | string | IANA zone used for calendar days (e.g. `Europe/Madrid`). |
| `presets` | object | Named parameter sets per method (e.g. `censure`, `reform`), with `min_attendance`. |
| `texts` | object | Free texts. Not normative. |

`profile.hash` in the rules is `HJ(profile document)`.

## 12. Opening notice

Published in the data repository when a voting opens, before any credential is issued. It fixes in public what cannot change afterwards.

```json
{
  "closes_at": null,
  "draw_commitment": null,
  "draw_round": null,
  "key": { "fingerprint": "…", "public_key": "…" },
  "opened_at": "2027-03-10T18:30:00Z",
  "quorum": { "forced": null, "met": true, "min_attendance": null, "required": 15 },
  "rules": { "…": "…" },
  "rules_hash": "…",
  "title": "…",
  "type": "opening",
  "version": 1,
  "voting_id": "…"
}
```

`closes_at` is the fixed closing time of a `final_link` voting, or `null` for `live`. `draw_commitment` is the commitment of the tie-break draw ([`draws.md`](draws.md) §5) or `null`; `draw_round` is its drand round for `final_link` votings, or `null`. `key` is `null` unless `mode` is `secret`. The opening notice is not part of the hash chain; a verifier MUST check that `rules`, `rules_hash`, `key`, `quorum` and the draw commitment and round of the board equal those of the opening notice and, for `final_link`, that `closed_at` equals `closes_at`.
